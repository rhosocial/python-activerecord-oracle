Fixed Oracle ``OracleStringAdapter._do_from_database`` to serialise Oracle 21c+ native JSON column values back to a JSON string when the model declares the field as ``str``. ``oracledb`` returns ``CLOB CHECK (... IS JSON)`` columns as ``oracledb.JSON`` wrappers (and on native JSON type 21c+, as parsed ``list``/``dict``); the previous adapter passed those wrappers through verbatim, so Pydantic rejected the value because ``preferences: Optional[str]`` could not accept a list. This cascaded into every ``test_logging_data_summarization`` test that round-trips a JSON column through ``JsonUser`` / ``AsyncJsonUser``. The adapter now ``json.dumps`` ``list``/``dict`` values when ``target_type is str``.
