Fixed Oracle query-domain `order_items.sql` schema mismatching the composite-PK `OrderItem` model class from `rhosocial.activerecord.testsuite.feature.basic.fixtures.models`. The model declares `__primary_key__ = ("order_id", "product_id")` and exposes only `order_id`, `product_id`, `quantity`, `unit_price`, but the previous Oracle schema used an auto-increment surrogate `id`, extra columns (`product_name`, `subtotal`), and a foreign key to a non-existent `orders` table. Loading the schema produced ORA-00942 (and the FK blocked the composite-PK load), which cascaded into every `order_item_class` / `async_order_item_class` test under `tests/.../feature/query/{basic,cte,set_operations}` failing at setup. The Oracle schema now mirrors the model.
