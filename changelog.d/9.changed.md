Adapt the Oracle formatters to core's expression / dialect split, where a capability probe answers whether a clause can be expressed and a parameter pair asks which spelling was requested: every two-spelling clause Oracle consumes now reads one parameter per side (`cycle` / `no_cycle`, `cache` / `no_cache`, `order` / `no_order`, `cascade` / `restrict`, `restart_identity` / `continue_identity`, `with_data` / `no_data`, `deferrable` / `not_deferrable`, `initially_deferred` / `initially_immediate`, `enforced` / `not_enforced`, `wait` / `no_wait`), setting both sides of a pair raises `ValueError`, and a request Oracle cannot spell raises `UnsupportedFeatureError` naming Oracle instead of rendering invalid SQL or silently dropping the clause; the Oracle-specific nodes use the same pair shape (`OracleCreateSequenceExpression`, `OracleAlterTypeFinalAction`, `OracleAlterTypeInstantiableAction`, `OracleObjectTypeDefinition`, `OracleCreateTypeBodyExpression`, `OracleCreateMaterializedViewExpression`, `OracleReadOnlyAction`, `OracleRowMovementAction`), with `is_final` / `is_instantiable` kept as compatibility aliases. Rendering defaults change with it: `CREATE SEQUENCE` no longer emits `NOCYCLE` / `NOORDER` when unspecified, `CREATE MATERIALIZED VIEW` emits no `BUILD` clause when unspecified, and constraint states render only when requested; callers that used the old falsy-as-negative spellings (`cycle=False`, `cache=0`, `order=False`, `final=False`, `instantiable=False`, `read_only=False`, `enable=False`, `editionable=False`, `query_rewrite=False`) must pass the negative parameter explicitly, or neither when the clause should be absent. Backend-facing, the dialect implements core's per-statement protocol split (`SchemaSupport` to `CreateSchemaSupport` / `DropSchemaSupport` / `NamespaceSupport`, `IndexSupport` to `CreateIndexSupport` / `DropIndexSupport` / `FulltextIndexSupport` / `IndexObjectSupport`, `AutoIncrementSupport` to `AutoIncrementColumnSupport`), `supports_auto_increment_column` replaces `supports_auto_increment` and answers `False`, the legacy `is_auto_increment` column flag routes through `format_identity_clause` so it fails by name below 12c instead of being dropped, and a formatter Oracle does not implement now raises `UnsupportedFeatureError` naming the missing formatter instead of `AttributeError`.
