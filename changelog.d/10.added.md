Add `OracleColumnTypeMixin` (`mixins/column_type.py`) and its 18-entry `ORACLE_COLUMN_TYPES` table as this backend's answer to core's new `ColumnTypeSupport` protocol, so the column class each common Python type means on Oracle is stated rather than inferred: one class per entry, none answered `None`, and every Oracle deviation carrying its reason — `float` / `Decimal` share `NumericColumn` because `NUMBER`, `BINARY_FLOAT` and `BINARY_DOUBLE` differ in width rather than in operations, the four sequence types answer `JSONColumn` because Oracle has no array column type in any release, `dict` answers `JSONColumn` with a storage that branches (native `JSON` from 21c, `CLOB` below), `date` / `time` answer `TimestampColumn` because Oracle's `DATE` carries a time component, and `timedelta` answers `NumericColumn` as a recorded core gap rather than a refusal. Add `OracleDataTypeSupport` (`protocols/data_type.py`), the stated protocol for the Oracle column data-type family, so the two halves of the suggestion question — which class an annotation means and how Oracle stores it — stay separate, and add `dialect/test_oracle_column_type.py`, which pins the composition, the table's completeness and version-invariance across 18c / 21c / 23ai, and resolution through the field accessor (including the `UseColumnType` escape hatch and the failure on an unregistered annotation). Compose `TrimMixin`, `LpadMixin` and `RpadMixin` on `OracleDialect`, so the new `trim` / `lpad` / `rpad` nodes render through Oracle's own spellings with no override; `RepeatMixin` is deliberately not composed, because Oracle has no `REPEAT` function.
