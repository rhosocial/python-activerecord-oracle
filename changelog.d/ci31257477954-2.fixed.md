Fixed Oracle backend suppressing optimistic-lock concurrent-update detection by reporting `affected_rows=1` for `UPDATE ... RETURNING INTO` statements that actually matched zero rows. The post-execution affected-count promotion to 1 now applies only to INSERTs; UPDATEs and DELETEs preserve the raw `cursor.rowcount` so `OptimisticLockMixin` and similar mixins correctly raise when no row was changed.
