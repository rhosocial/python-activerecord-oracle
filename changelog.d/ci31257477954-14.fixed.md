Fixed two residual Oracle CI failures uncovered by CI run 31354570408:

1. ``tests/rhosocial/.../feature/query/schema/orders.sql``: removed ``ON DELETE CASCADE`` from the ``fk_orders_user`` foreign key.  Oracle honoured the cascade and deleted the orphan ``Order`` rows, so the testsuite's ``TestSyncEmptyRelation.test_belongs_to_none`` and the matching async test observed ``None`` from ``Order.query().with_('user').one()`` and failed with ``assert None is not None``.  With no cascade clause the delete is rejected by Oracle's FK enforcement and the testsuite falls back to its early-return path, matching the behaviour of the MySQL backend.

2. ``tests/providers/basic_connection.py``: defensive ``AsyncTestUser.__backend__ = None`` in ``setup_sync_pool_and_model``.  When the test_savepoint_api module imports both the sync and async savepoint files, pytest-asyncio 1.4.0 in auto mode interleaves async and sync tests, and a stale ``AsyncTestUser.__backend__`` from a previous async test was being read during the sync transaction setup, surfacing the sync ``TestSavepointCreate`` failures (e.g. ``isinstance(name, str)`` was given a coroutine).  Clearing it on every sync setup guarantees a clean slate.
