Five Oracle CI failures uncovered by run 31365047287:

1. ``src/.../oracle/adapters.py``: ``OracleDecimalAdapter`` now registers
   ``(float, float)`` so model fields declared ``balance: float`` resolve
   to an adapter instead of silently being dropped from the column
   adapter map.

2. ``src/.../oracle/mixins/backend_mixin.py``: ``get_default_adapter_suggestions``
   adds the ``float -> float`` suggestion so the lookup at runtime
   succeeds for the new ``OracleDecimalAdapter`` registration.

3. ``src/.../oracle/backend.py``: explicit ``_handle_auto_commit`` plus a
   ``_handle_auto_commit_if_needed`` invocation at the tail of
   ``_execute_with_returning_into``. Oracle thin connections default to
   ``autocommit=False``, so without this hook DML that goes through the
   RETURNING-INTO path silently stays in the session's transaction and
   is rolled back as soon as the Worker connection closes - which broke
   ``test_parallel_update``/``test_parallel_delete`` (worker DML never
   reached the main process's verification queries).

4. ``src/.../oracle/async_backend.py``: matching async override of
   ``_handle_auto_commit`` for the same reason on the async backend.

5. ``src/.../oracle/dialect.py``: ``OracleDialect.supports_for_update``
   now returns ``True``. Without it the worker transaction-isolation
   testsuite took the non-locking fallback, which races under
   concurrent workers on Oracle (no implicit database-level
   serialization the way SQLite has) and surfaced as
   ``test_concurrent_transactions_isolation`` lost-update failures.
