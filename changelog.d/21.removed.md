Remove `supports_partition_info()` and `list_partitions()`. The aggregate probe was deleted by core's four-family split and answered `False` for every server while Oracle's own `supports_partition_metadata_introspection()` (true from 11g) is the capability the CLI's `partitions` type reads. Partition state is now answered through core's neutral `get_partition_state()`, whose `scheme` is `None` for an unpartitioned table; the old record list has no compatibility layer.
