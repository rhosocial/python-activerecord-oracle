## Quick Start

```python
from typing import ClassVar, Optional

from rhosocial.activerecord.base import FieldProxy
from rhosocial.activerecord.backend.impl.oracle.backend import OracleBackend
from rhosocial.activerecord.backend.impl.oracle.config import OracleConnectionConfig
from rhosocial.activerecord.backend.expression import CreateTableExpression
from rhosocial.activerecord.backend.expression.statements import (
    ColumnConstraint,
    ColumnConstraintType,
    ColumnDefinition,
)
from rhosocial.activerecord.backend.expression.types import IntegerType, VarCharType
from rhosocial.activerecord.model import ActiveRecord


class User(ActiveRecord):
    __table_name__ = "users"

    id: Optional[int] = None
    name: str
    email: str

    c: ClassVar[FieldProxy] = FieldProxy()


User.configure(
    OracleConnectionConfig(
        host="localhost",
        port=1521,
        database="ORCLPDB1",
        username="system",
        password="password",
    ),
    OracleBackend,
)

dialect = User.__backend__.dialect
User.__backend__.execute(*CreateTableExpression(
    dialect,
    "users",
    columns=[
        ColumnDefinition(
            dialect, "id", IntegerType(dialect),
            constraints=[ColumnConstraint(dialect, ColumnConstraintType.PRIMARY_KEY,
                is_auto_increment=True)],
        ),
        ColumnDefinition(dialect, "name", VarCharType(dialect, 100)),
        ColumnDefinition(dialect, "email", VarCharType(dialect, 255)),
    ],
).to_sql())

user = User(name="Alice", email="alice@example.com")
user.save()
rows = User.query().where(User.c.email == "alice@example.com").all()
```

### Async

`AsyncOracleBackend` exposes the same API. Method names are identical; add
`await`.

```python
from rhosocial.activerecord.backend.impl.oracle.backend import AsyncOracleBackend
from rhosocial.activerecord.model import AsyncActiveRecord


class User(AsyncActiveRecord):
    ...


User.configure(config, AsyncOracleBackend)
rows = await User.query().where(User.c.email == "alice@example.com").all()
```

## Oracle-Specific Features

### `RETURNING INTO`

`INSERT`, `UPDATE` and `DELETE` all return the affected row in a single
round-trip, so a generated id is available straight after `save()` without a
follow-up `SELECT`. The `*_expressions` variant is **not** supported:
`supports_returning_expressions()` is `False`.

### Flashback queries

```python
User.query().where(
    "id = ? AS OF TIMESTAMP (SYSTIMESTAMP - INTERVAL '1' HOUR)",
    (1,),
).all()
```

### Hierarchical queries

```python
Employee.query().where(
    "START WITH manager_id IS NULL CONNECT BY PRIOR emp_id = manager_id"
).all()
```

### Spatial types

`SDO_GEOMETRY` columns and spatial indexes are available through
`supports_spatial_type()` and `supports_spatial_index()`.

## Schema Names

In Oracle a schema is the owning user, so `schema_name` names a user and
identifiers fold to upper case:

```python
class Order(ActiveRecord):
    __schema_name__ = "app"   # this is a user
    __tablename__ = "orders"
```

```sql
-- generated
SELECT * FROM "APP"."ORDERS"
```

Two things to keep in mind:

- **Identifiers are folded upper.** A lower-case `schema_name` becomes upper
  case in the SQL, which is what Oracle stores. A quoted mixed-case name would
  not match the user created by an unquoted `CREATE USER`.
- **Columns take three parts.** `` "APP"."ORDERS"."ID" `` is valid here, unlike
  MySQL, SQL Server and ClickHouse where a column reference stops at two.

DDL statements take a `schema_name` of their own — views, types, indexes,
sequences, domains, functions and triggers all accept it, defaulting to `None`
for an unqualified reference. `__schema_name__` is not consulted when DDL is
built, so a migration names the schema it means.

`get_current_schema()` reads `SYS_CONTEXT('USERENV','CURRENT_SCHEMA')`, selected
`FROM DUAL` because the value function cannot stand alone in a SELECT list.

## Known Limitations

- **No connection pooling.** The config class accepts pooling fields but the
  backend does not consume them; `connect()` opens one persistent
  connection. The one exception is bulk worker concurrency, which does read
  `pool_max` to cap process count.
- **No `IF EXISTS` / `IF NOT EXISTS` on many DDL statements.**
  `add_column_if_not_exists`, `drop_column_if_exists`, `drop_constraint_if_exists`,
  `if_exists_table`, `if_not_exists_table`, `if_not_exists_view`,
  `index_if_exists` and `index_if_not_exists` are all `False` at every probed
  version.
- **`MERGE` needs 9.0+.** `supports_merge_statement()` gates at 9.0; below
  that, conditional upserts have to go through `RETURNING` plus application
  logic.
- Also unsupported: `for_update`, `for_share`, `filter_clause`, `fk_match`,
  `insert_ignore`, `isolation_level_in_begin`, `lock_timeout`,
  `replace_into`, `returning_expressions`, `qualify_clause`,
  `create_schema`, `drop_schema`, `attach_partition`, `detach_partition`.
- Arrays are not a native column type here. Oracle has `VARRAY`, but this
  backend exposes no array `DataType` for it; model `list[...]` fields need
  a type adapter.

## Testing

Tests require a reachable Oracle instance and must run serially. CI uses
`gvenzl/oracle-xe:18-slim`, `gvenzl/oracle-xe:21-slim` and
`gvenzl/oracle-free:23-slim`, and restarts the container before each run.

```bash
export PYTHONPATH=src:tests
.venv3.14-ubuntu26.04/bin/pytest tests/
```

The shared contract suite lives in
[python-activerecord-testsuite](https://github.com/rhosocial/python-activerecord-testsuite):

```bash
PYTHONPATH=tests .venv3.14-ubuntu26.04/bin/pytest \
  ../python-activerecord-testsuite/src/rhosocial/activerecord/testsuite/feature/
```
